# Запуск и сопровождение МаноБанка

Корень проекта: `D:\Учеба\Практика`. Приложение: `site`. Команды ниже выполняются в PowerShell из корня проекта. `tools/project.ps1` использует установленные PHP, Composer и Node.js и локальные каталоги временных данных. Точные версии зависимостей зафиксированы в `site/composer.lock` и `site/package-lock.json`.

Кредит и вклад используют точные рациональные числа; пенсия — точные конечные десятичные значения. Дроби не обрезаются перед следующей операцией. В снимке версии 2 рациональная сумма может храниться строкой `числитель/знаменатель`; представление переводит её в целые рубли только для выдачи. Старые десятичные снимки также читаются. Локально включено установленное расширение GMP для ускорения арифметики; при его отсутствии библиотека имеет более медленную программную реализацию. При размещении наличие GMP следует проверить отдельно.

## Первый запуск

1. Создать `site/.env` из `site/.env.example`, если локального файла ещё нет. Существующий файл не перезаписывать: он содержит индивидуальный ключ и настройки.
2. Восстановить зависимости: `& .\tools\project.ps1 composer install` и `& .\tools\project.ps1 npm ci`.
3. Только для нового `.env` без ключа: `& .\tools\project.ps1 php artisan key:generate`. Не менять ключ работающего приложения без отдельной процедуры: зашифрованные данные и сессии зависят от него.
4. Создать отсутствующие таблицы: `& .\tools\project.ps1 php artisan migrate --force`.
5. Заполнить пять публичных продуктов: `& .\tools\project.ps1 php artisan db:seed --force`. Сидер добавляет отсутствующие записи, существующие не переписывает.
6. Собрать интерфейс: `& .\tools\project.ps1 npm run build`.
7. Задать отдельный пароль приложения: `& .\tools\project.ps1 php artisan manobank:admin-password`. Команда скрывает ввод и запрашивает повтор. Email администратора — `supp.manobank@mail.ru`. Пароль административного приложения не является паролем почтового ящика.

Локальный запуск:

```powershell
& .\tools\project.ps1 php -S 127.0.0.1:8000 -t public app/Modules/Maintenance/Server/router.php
```

Открыть `http://127.0.0.1:8000/`; административный вход — `/admin/login`. Остановить сервер сочетанием Ctrl+C. Встроенный сервер предназначен для локальной проверки. Относительный путь к маршрутизатору используется, чтобы избежать обнаруженного искажения кириллицы при запуске штатной команды сервера в Windows. Рабочий каталог PHP должен быть `site`; помощник устанавливает его сам.

В разделе «История расчётов» отметить нужные записи галочками и нажать существующую кнопку «Выгрузить XLSX». Без выбора кнопка неактивна. Файл содержит только отмеченные расчёты: исходные данные и итоги на листе «Расчёты», полные графики на листе «Графики». При переходе на другую страницу списка выбор нужно сделать заново.

## Настройки и рабочие данные

- Приложение использует SQLite; файл базы находится в `site/database/database.sqlite` и исключён из Git. В базе сохраняются калькуляторы, снимки результатов, хеш административного пароля и техническая статистика.
- Публичные состояния личного кабинета не отправляют и не сохраняют введённые пароли и номера карт. Получатель письма не добавляется в снимок расчёта.
- `.env`, ключ приложения, SMTP-пароль, сессии, журналы, кэш шрифтов PDF и резервные копии не публикуются.
- `APP_URL` должен содержать фактический основной адрес приложения: он используется в canonical, robots.txt и sitemap.xml. На сервере нужен `APP_ENV=production`, `APP_DEBUG=false`, HTTPS и `SESSION_SECURE_COOKIE=true`. Для сессий предусмотрен `SESSION_ENCRYPT=true`.
- Часовой пояс банка — `Europe/Samara`, UTC+4. Календарь вклада определяется серверным временем банка.
- Корень веб-сервера на хостинге — исключительно `site/public`. Корень всего репозитория, база, `.env`, исходные документы и `temp` не должны обслуживаться как публичные файлы.

## Почта

Код отправляет короткое письмо и один PDF пользователю автоматически, без административного одобрения и без копии администратору. Выделенный транспорт `mailru`: `smtp.mail.ru`, порт 465, SMTPS, отправитель `supp.manobank@mail.ru`. Настройки сверены с [официальной справкой Mail](https://help.mail.ru/mail/login/mailer/); для внешнего приложения требуется [отдельный пароль](https://help.mail.ru/mail/faq/password/external/).

В локальном `.env` владелец задаёт `MAIL_PASSWORD` и включает `MANOBANK_MAIL_ENABLED=true`, затем очищает кэш командой `& .\tools\project.ps1 php artisan config:clear`. Пароль нельзя присылать в чат или помещать в Git. До подключения функция возвращает ошибку; транспорт `log` не подменяет настоящую отправку. Успешная передача серверу SMTP и фактическое получение письма — разные проверки. После подключения необходимо получить контрольные письма от всех пяти калькуляторов, открыть PDF и сверить график. Пока эта внешняя проверка не выполнена, доставка не считается подтверждённой.

## Резервная копия и проверка восстановления

Создать копию:

```powershell
& .\tools\project.ps1 php artisan manobank:backup
```

Архив создаётся в `temp/runtime/backups`. Внутри — исходники приложения, lock-файлы, собранный интерфейс, утверждённые входная группа и карта, согласованный снимок SQLite и манифест SHA-256. Снимок базы создаётся SQLite-командой `VACUUM INTO`, а не копированием открытого файла. В копию не входят `.env`, служебные правила, Git, vendor и node_modules. Архив содержит рабочие данные и должен храниться локально; он не предназначен для публикации.

Проверить полученный архив, подставив его фактический путь:

```powershell
& .\tools\project.ps1 php artisan manobank:verify-backup 'полный путь к созданному архиву.zip'
```

Проверка отклоняет выходящие за каталог пути и ссылки, сверяет контрольные суммы, восстанавливает исходники и базу в отдельную папку внутри `temp/runtime`, запускает новый процесс PHP, проверяет целостность SQLite, страницу сайта и контрольную ипотеку. Должны получиться HTTP 200 и 201, платёж 14 080 ₽ и рекомендуемая зарплата 35 200 ₽. После проверки созданная проверочная папка удаляется; рабочая база не заменяется.

Проверочный процесс использует установленные сторонние зависимости из локального `site/vendor`; совпадение `composer.lock` проверяется до запуска. Собственные классы загружаются из восстановленной копии, что дополнительно проверяется по пути исходного файла. Проверка не подтверждает установку зависимостей на новом внешнем сервере. Для нового сервера зависимости устанавливаются по lock-файлу; `.env` и ключ восстанавливаются отдельно из защищённого хранилища владельца.

Полное восстановление рабочей среды следует начинать в новом каталоге, не поверх действующего сайта: проверить архив, восстановить зависимости, отдельно задать защищённую конфигурацию и только после контрольных проверок переключать веб-сервер. Команда проверки намеренно не заменяет рабочие файлы и базу.

## Пакет размещения

После сборки интерфейса команда `& .\tools\project.ps1 php artisan manobank:package` создаёт `docs/releases/МаноБанк_сайт.zip`. В пакет входят исходники, lock-файлы, готовые ресурсы интерфейса, `.env.example`, два утверждённых изображения и инструкция. Рабочая база, `.env`, Git, локальные правила и установленные сторонние зависимости в него не входят. Манифест содержит контрольные суммы файлов. Это пакет для развёртывания, а не резервная копия рабочих данных.

На сервере после распаковки нужны установка Composer-зависимостей по lock-файлу, отдельная защищённая конфигурация, SQLite и миграции с сидером. Публикуемый каталог — `site/public`; папку `visualizations/manobank` сохранить рядом с `site`, поскольку изображения обслуживаются контроллером по фиксированным путям. Сам факт создания пакета не подтверждает размещение в Интернете.

## Проверки и статистика

```powershell
& .\tools\project.ps1 composer test
& .\tools\project.ps1 npm run build
& .\tools\project.ps1 php artisan manobank:statistics
& .\tools\project.ps1 php artisan manobank:statistics --verification
```

Статистика содержит число запросов, ошибки, длительность обработки и разбивку по именам маршрутов. Она не содержит тела форм, адресов получателей, IP, паролей и номеров карт. Автоматические тесты помечаются как проверочные. Для ручного проверочного запуска перед сервером задать `$env:MONITORING_VERIFICATION='true'` в его процессе; обычный запуск использует значение `false` из примера конфигурации. Проверочные запросы анализируются отдельно и не выдаются за посещения реальных клиентов.

## Типовые неисправности

| Признак | Проверка и действие |
| --- | --- |
| Нет стилей или ошибка manifest | Выполнить сборку интерфейса; проверить `site/public/build/manifest.json`. После изменения сборки перезагрузить страницу. |
| Не найдена таблица | Проверить выбранный файл SQLite и выполнить `artisan migrate`; не применять `migrate:fresh` к рабочим данным. |
| Администратор не может войти | Проверить Email и отдельно задать пароль приложения локальной командой. После пяти неудачных попыток подождать минуту. |
| Письмо не отправляется | Проверить включение отправки, пароль внешнего приложения, доступ хостинга к SMTP 465 и официальный режим внешних сервисов Mail. Ошибка не означает, что письмо принято сервером. |
| Ошибка 419 | Сессия или CSRF-токен устарели: обновить страницу и повторить ввод. Проверить HTTPS, домен и cookie на сервере. |
| База недоступна для записи | Проверить права процесса PHP на SQLite и содержащую её папку; не переносить базу в публичный каталог. |
| Порт 8000 занят | Остановить только свой ранее запущенный сервер или выбрать свободный порт и соответствующий локальный адрес. Чужие процессы не завершать. |

Проверка внешнего HTTPS, условий выбранного хостинга, SMTP-доставки и окончательного публичного адреса выполняется после предоставления доступа к размещению. Локальная проверка не заменяет эти действия.
