## Первый запуск

1. Создать `site/.env` из `site/.env.example`, если локального файла ещё нет. Существующий файл не перезаписывать: он содержит индивидуальный ключ и настройки.
2. Восстановить зависимости: `& .\tools\project.ps1 composer install` и `& .\tools\project.ps1 npm ci`.
3. Только для нового `.env` без ключа: `& .\tools\project.ps1 php artisan key:generate`. Не менять ключ работающего приложения без отдельной процедуры: зашифрованные данные и сессии зависят от него.
4. Создать отсутствующие таблицы: `& .\tools\project.ps1 php artisan migrate --force`.
5. Заполнить пять публичных продуктов: `& .\tools\project.ps1 php artisan db:seed --force`. Сидер добавляет отсутствующие записи, существующие не переписывает.
6. Собрать интерфейс: `& .\tools\project.ps1 npm run build`.
7. Задать отдельный пароль приложения: `& .\tools\project.ps1 php artisan manobank:admin-password`. Команда скрывает ввод и запрашивает повтор. Email администратора — `supp.manobank@mail.ru`. Пароль административного приложения не является паролем почтового ящика.

Локальный запуск:

```powershell
& .\tools\project.ps1 php -S 127.0.0.1:8000 -t public app/Modules/Maintenance/Server/router.php
```

Открыть `http://127.0.0.1:8000/`; административный вход — `/admin/login`. Остановить сервер сочетанием Ctrl+C. Встроенный сервер предназначен для локальной проверки. Относительный путь к маршрутизатору используется, чтобы избежать обнаруженного искажения кириллицы при запуске штатной команды сервера в Windows. Рабочий каталог PHP должен быть `site`; помощник устанавливает его сам.

В разделе «История расчётов» отметить нужные записи галочками и нажать существующую кнопку «Выгрузить XLSX». Без выбора кнопка неактивна. Файл содержит только отмеченные расчёты: исходные данные и итоги на листе «Расчёты», полные графики на листе «Графики». При переходе на другую страницу списка выбор нужно сделать заново.

## Настройки и рабочие данные

- Приложение использует SQLite; файл базы находится в `site/database/database.sqlite` и исключён из Git. В базе сохраняются калькуляторы, снимки результатов, хеш административного пароля и техническая статистика.
- Публичные состояния личного кабинета не отправляют и не сохраняют введённые пароли и номера карт. Получатель письма не добавляется в снимок расчёта.
- `.env`, ключ приложения, SMTP-пароль, сессии, журналы, кэш шрифтов PDF и резервные копии не публикуются.
- `APP_URL` должен содержать фактический основной адрес приложения: он используется в canonical, robots.txt и sitemap.xml. На сервере нужен `APP_ENV=production`, `APP_DEBUG=false`, HTTPS и `SESSION_SECURE_COOKIE=true`. Для сессий предусмотрен `SESSION_ENCRYPT=true`.
- Часовой пояс банка — `Europe/Samara`, UTC+4. Календарь вклада определяется серверным временем банка.
- Корень веб-сервера на хостинге — исключительно `site/public`. Корень всего репозитория, база, `.env`, исходные документы и `temp` не должны обслуживаться как публичные файлы.

## Почта

Код отправляет короткое письмо и один PDF пользователю автоматически, без административного одобрения и без копии администратору. Выделенный транспорт `mailru`: `smtp.mail.ru`, порт 465, SMTPS, отправитель `supp.manobank@mail.ru`. Настройки сверены с [официальной справкой Mail](https://help.mail.ru/mail/login/mailer/); для внешнего приложения требуется [отдельный пароль](https://help.mail.ru/mail/faq/password/external/).

В локальном `.env` владелец задаёт `MAIL_PASSWORD` и включает `MANOBANK_MAIL_ENABLED=true`, затем очищает кэш командой `& .\tools\project.ps1 php artisan config:clear`. Пароль нельзя присылать в чат или помещать в Git. До подключения функция возвращает ошибку; транспорт `log` не подменяет настоящую отправку. Успешная передача серверу SMTP и фактическое получение письма — разные проверки. После подключения необходимо получить контрольные письма от всех пяти калькуляторов, открыть PDF и сверить график. Пока эта внешняя проверка не выполнена, доставка не считается подтверждённой.

## Резервная копия и проверка восстановления

Создать копию:

```powershell
& .\tools\project.ps1 php artisan manobank:backup
```

Архив создаётся в `temp/runtime/backups`. Внутри — исходники приложения, lock-файлы, собранный интерфейс, утверждённые входная группа и карта, согласованный снимок SQLite и манифест SHA-256. Снимок базы создаётся SQLite-командой `VACUUM INTO`, а не копированием открытого файла. В копию не входят `.env`, служебные правила, Git, vendor и node_modules. Архив содержит рабочие данные и должен храниться локально; он не предназначен для публикации.

Проверить полученный архив, подставив его фактический путь:

```powershell
& .\tools\project.ps1 php artisan manobank:verify-backup 'полный путь к созданному архиву.zip'
```

Проверка отклоняет выходящие за каталог пути и ссылки, сверяет контрольные суммы, восстанавливает исходники и базу в отдельную папку внутри `temp/runtime`, запускает новый процесс PHP, проверяет целостность SQLite, страницу сайта и контрольную ипотеку. Должны получиться HTTP 200 и 201, платёж 14 080 ₽ и рекомендуемая зарплата 35 200 ₽. После проверки созданная проверочная папка удаляется; рабочая база не заменяется.

Проверочный процесс использует установленные сторонние зависимости из локального `site/vendor`; совпадение `composer.lock` проверяется до запуска. Собственные классы загружаются из восстановленной копии, что дополнительно проверяется по пути исходного файла. Проверка не подтверждает установку зависимостей на новом внешнем сервере. Для нового сервера зависимости устанавливаются по lock-файлу; `.env` и ключ восстанавливаются отдельно из защищённого хранилища владельца.

Полное восстановление рабочей среды следует начинать в новом каталоге, не поверх действующего сайта: проверить архив, восстановить зависимости, отдельно задать защищённую конфигурацию и только после контрольных проверок переключать веб-сервер. Команда проверки намеренно не заменяет рабочие файлы и базу.

## Пакет размещения

После сборки интерфейса команда `& .\tools\project.ps1 php artisan manobank:package` создаёт `docs/releases/МаноБанк_сайт.zip`. В пакет входят исходники, lock-файлы, готовые ресурсы интерфейса, `.env.example`, два утверждённых изображения и инструкция. Рабочая база, `.env`, Git, локальные правила и установленные сторонние зависимости в него не входят. Манифест содержит контрольные суммы файлов. Это пакет для развёртывания, а не резервная копия рабочих данных.

На сервере после распаковки нужны установка Composer-зависимостей по lock-файлу, отдельная защищённая конфигурация, SQLite и миграции с сидером. Публикуемый каталог — `site/public`; папку `visualizations/manobank` сохранить рядом с `site`, поскольку изображения обслуживаются контроллером по фиксированным путям. Сам факт создания пакета не подтверждает размещение в Интернете.

Проверочные запросы анализируются отдельно и не выдаются за посещения реальных клиентов.

## Типовые неисправности

| Признак | Проверка и действие |
| --- | --- |
| Нет стилей или ошибка manifest | Выполнить сборку интерфейса; проверить `site/public/build/manifest.json`. После изменения сборки перезагрузить страницу. |
| Не найдена таблица | Проверить выбранный файл SQLite и выполнить `artisan migrate`; не применять `migrate:fresh` к рабочим данным. |
| Администратор не может войти | Проверить Email и отдельно задать пароль приложения локальной командой. После пяти неудачных попыток подождать минуту. |
| Письмо не отправляется | Проверить включение отправки, пароль внешнего приложения, доступ хостинга к SMTP 465 и официальный режим внешних сервисов Mail. Ошибка не означает, что письмо принято сервером. |
| Ошибка 419 | Сессия или CSRF-токен устарели: обновить страницу и повторить ввод. Проверить HTTPS, домен и cookie на сервере. |
| База недоступна для записи | Проверить права процесса PHP на SQLite и содержащую её папку; не переносить базу в публичный каталог. |
| Порт 8000 занят | Остановить только свой ранее запущенный сервер или выбрать свободный порт и соответствующий локальный адрес. Чужие процессы не завершать. |

Внешний HTTPS, временный публичный адрес, SMTP-доставка и настоящий вход администратора проверены на VPS. Выгрузка через защищённый HTTP-маршрут вернула XLSX только с двумя выбранными расчётами и полными графиками на 480 строк.

## Подготовка Linux-сервера и порядок размещения

Требования именно текущего `composer.lock`: PHP **не ниже 8.4.1**, Composer 2, расширения из раздела «Требования к среде» README, дополнительно `pdo_sqlite` и `sqlite3`. Для скорости точных расчётов рекомендуется GMP. Предпочтителен PHP 8.5, на котором выполнен локальный регрессионный прогон. Проверять нужно и CLI, и обслуживающий сайт PHP-FPM: это могут быть разные версии и наборы расширений. `--ignore-platform-reqs` не использовать. Если на сервере уже работает другое приложение, его версию PHP и конфигурацию веб-сервера не заменять.

Пакет содержит готовый `public/build`, поэтому Node.js на рабочем сервере не обязателен. Он нужен только для повторной сборки. База приложения — SQLite; отдельный MySQL-сервер МаноБанку не требуется. Почта отправляется синхронно через выделенный транспорт `mailru`; запуск обработчика очереди для этой функции не нужен.

### Размещение файлов

Ниже описан порядок подготовки новой копии. У действующего экземпляра используются `/srv/manobank`, пользователь `manobank`, адрес и сокет из таблицы выше. При повторном размещении сначала проверяется фактическое состояние сервера. Сохраняется структура пакета:

```text
/srv/manobank/
  site/                 приложение и закрытая конфигурация
    public/             единственный корень веб-сервера
    database/           закрытая SQLite
    storage/            журналы, сессии и шрифты PDF
    bootstrap/cache/    служебный кэш
  visualizations/       утверждённые изображения, соседний каталог site
  temp/reports/         временные файлы формирования PDF
  temp/runtime/         эксплуатационные резервные копии
```

Перед копированием проверить SHA-256 архива и каждый файл по `release-manifest.json`. Распаковывать в новый закрытый каталог, не поверх работающего приложения. Не добавлять в него локальную рабочую базу, `.env` или SSH-ключи автоматически. Два изображения рядом с `site` должны сохраниться: их выдаёт контроллер контактов.

### Установка зависимостей и конфигурация

До установки создать отсутствующие служебные каталоги `storage/app/private`, `storage/framework/cache/data`, `storage/framework/sessions`, `storage/framework/views`, `storage/fonts`, `storage/logs`, `bootstrap/cache` и соседние `temp/reports`, `temp/runtime/backups`. Composer вызывает обнаружение пакетов, поэтому `bootstrap/cache` должен существовать уже к этому моменту.

Затем из каталога `site` под отдельным пользователем размещения с подходящей версией PHP:

```bash
composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
composer check-platform-reqs --no-dev
composer audit --locked --no-dev
test -f .env || cp .env.example .env
test -f database/database.sqlite || touch database/database.sqlite
```

Дать процессу PHP запись только в перечисленные служебные каталоги и каталог SQLite с самой базой. Исходники и `vendor` доступны для чтения, но не требуют записи из веб-процесса. Не применять `chmod 777`. Конфигурация `.env` читается только владельцем и необходимой группой процесса; она не должна быть доступна посторонним пользователям или по HTTP.

На действующем VPS служебный каталог `/srv/manobank/temp/runtime` принадлежит `root:manobank` и имеет права `1770`: группа может создавать изолированные каталоги восстановления, а sticky bit защищает принадлежащие root элементы от удаления пользователем приложения. Вложенный каталог установки `deployment` закрыт правами `0700`; каталоги PHP и резервных копий принадлежат `manobank` и имеют права `0750`. Перед исправлением прав содержимое и отсутствие символьных ссылок проверены. Эти права не распространяются на соседние проекты.

PHP 8.5 установлен из официального репозитория `packages.sury.org/php`, Composer 2.11.3 — официальным установщиком с проверкой SHA-384. Старый PPA использовался для официального пакета миграции источника, после чего удалён. Файл `app/Modules/Maintenance/Server/php-packages.pref` закрепляет запрет замены PHP 8.3 пакетами этого источника. Серверные команды установки зависимостей выполняются через `php8.5 /usr/local/bin/composer`; `check-platform-reqs --no-dev` прошёл, `audit --locked --no-dev` не выявил предупреждений безопасности.

Настроить `.env` без публикации секретов:

- `APP_ENV=production`, `APP_DEBUG=false`, `LOG_LEVEL=warning`.
- `APP_URL` — реальный внешний адрес. До его определения не подставлять выдуманный домен.
- `DB_CONNECTION=sqlite`, `DB_DATABASE` — абсолютный путь к закрытому файлу этой копии.
- `SESSION_ENCRYPT=true`; `SESSION_SECURE_COOKIE=true` после настройки HTTPS.
- `MONITORING_VERIFICATION=false` для обычного запуска; проверочную нагрузку учитывать отдельно.
- `MANOBANK_MAIL_ENABLED=false` до отдельного подключения Mail.ru. После защищённого ввода пароля внешнего приложения — `true`. Пароль почты не является паролем админки.

Только у новой копии с пустым `APP_KEY` выполнить `php artisan key:generate`. Затем `php artisan migrate --force`, `php artisan db:seed --force` и интерактивно `php artisan manobank:admin-password`. Существующие ключ и базу при обновлении сохранять. `composer setup`, `migrate:fresh` и автоматическое повторное создание ключа не использовать для рабочего экземпляра. Завершить `php artisan config:cache` и `php artisan view:cache`.

### Веб-сервер и приёмка

Основа настройки — [официальное руководство Laravel по размещению](https://laravel.com/docs/13.x/deployment). У Nginx корень указывает только на `site/public`; запросы приложения передаются в `public/index.php` через `try_files`, а FastCGI — в отдельный согласованный сокет PHP-FPM. Принцип передачи и `SCRIPT_FILENAME` описан в [документации Nginx](https://nginx.org/en/docs/http/ngx_http_fastcgi_module.html). Остальные PHP-файлы и скрытые файлы не обслуживаются публично. Не заменять существующий виртуальный хост другого приложения. До изменения Nginx проверяются имя сервера, сертификат, конфликт портов и результат `nginx -t`.

Для окончательной приёмки опубликованной копии проверить:

1. HTTPS и основной адрес, переходы, пять калькуляторов, контакты и оба изображения.
2. Пустое состояние, сброс, ограничения и пять финансовых эталонов из отчёта проверки.
3. HTTP-отказ для `/.env`, `/composer.json`, `/database/database.sqlite`, `/vendor/`, `/temp/` и служебных путей; содержимое закрытых файлов нигде не возвращается.
4. Административный вход, выбор записей и XLSX; отсутствие открытого доступа к истории без авторизации.
5. Реальные письма с PDF от всех пяти продуктов на согласованный контрольный адрес, затем подтверждение получения и открытия файлов. TLS-проверка порта сама по себе не подтверждает авторизацию или доставку.
6. `canonical`, `robots.txt`, `sitemap.xml` с фактическим внешним адресом; отсутствие локального адреса в выдаче.
7. Создание резервной копии и её отдельную проверку, права каталогов и запись SQLite.

На действующем экземпляре HTTP перенаправляется на HTTPS. Сертификат продлевается через webroot `/srv/manobank/acme`; включён `certbot.timer`, существующий deploy-hook проверяет Nginx и перечитывает его конфигурацию после продления. Конфигурации Nginx и PHP-FPM для МаноБанка сохранены в `app/Modules/Maintenance/Server`. Проверки `nginx -t` и `php-fpm8.5 -t` прошли.

Приложение размещено, Mail.ru и административный доступ подключены и проверены. Резервная копия после смены пароля создана с правами `0600` и успешно проверена изолированным восстановлением. Появление страниц в поисковой выдаче не проверялось; доступность sitemap сама по себе его не доказывает.

Расчёты и отправка писем используют отдельные счётчики ограничений: 30 расчётов и 5 отправок в минуту для одного сетевого адреса. Расчёт не расходует лимит писем. Общий счётчик ранее вызывал HTTP 429 при третьем письме в последовательности расчётов; ошибка воспроизведена регрессионным тестом и исправлена разделением префиксов. Полный прогон после исправления: 63 теста, 1712 проверок, без ошибок. Первые два принятых письма при возобновлении проверки не дублировались.
